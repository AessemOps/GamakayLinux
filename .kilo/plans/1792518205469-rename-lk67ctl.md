# Rename the app to `lk67ctl`

## Why

The project supports exactly one board — the GamaKay LK67 — and is unofficial:
GamaKay ships only its Windows Electron app and has no relationship with this
one. `GamakayLinux` puts their trademark in the product name (package, binaries,
desktop entry, AppStream id) for a tool that covers one model, which overstates
both the scope and any affiliation.

`lk67ctl` fixes both: it names the model the tool is for, and it contains no
vendor trademark. "GamaKay LK67" stays in prose and in the AppStream summary as
nominative use — saying what the board *is* — with an explicit
not-affiliated notice in the README.

The icon is already drawn for the project (GPL-3.0-or-later, no vendor
artwork), so no icon change is needed.

## Naming

| thing | before | after |
|---|---|---|
| product / package | `GamakayLinux` / `gamakaylinux` | `lk67ctl` |
| CLI binary | `gamakay` | `lk67ctl` |
| GUI binary | `gamakay-gui` | `lk67-gui` |
| crates | `gamakay-{core,hidraw,cli,gui}` | `lk67-{core,hidraw,cli,gui}` |
| Rust modules | `gamakay_core`, … | `lk67_core`, … |
| config dir | `~/.config/gamakay` | `~/.config/lk67ctl` |
| desktop file | `gamakay.desktop` | `lk67ctl.desktop` |
| AppStream id/file | `io.github.aessemops.gamakaylinux` | `io.github.aessemops.lk67ctl` |
| icons | `gamakay.{png,svg}` | `lk67ctl.{png,svg}` |
| udev rule | `70-gamakay.rules` | `70-lk67ctl.rules` |
| repo | `AessemOps/GamakayLinux` | `AessemOps/lk67ctl` |

## Steps

1. `git mv` the four crates, the desktop/AppStream/install/udev/icon files.
2. Replace identifiers across the tree: crate and binary names, module paths,
   package name, desktop/AppStream ids, config dir, repo URLs, Makefile,
   nfpm, AppImage `AppRun`, release workflow (archive prefix
   `lk67ctl-<v>/`, artifact names, the post-install verification paths),
   `scripts/check-release-version.sh`, `scripts/make-icons.sh`, docs, AGENTS.
3. `~/.config/lk67ctl/profiles`, falling back to the old `~/.config/gamakay`
   when the new directory does not exist — an existing profile keeps working.
4. Packaging migration: the Arch package `provides`/`conflicts`/`replaces`
   `gamakaylinux`; the deb (`Conflicts`/`Replaces`) and rpm (`Obsoletes`) get
   the same, so installing 0.3.0 replaces 0.2.1 rather than colliding with it.
5. README: new title, an explicit "unofficial, not affiliated with GamaKay"
   notice, new package names in the install table, `lk67ctl` in every example.
6. CHANGELOG `Unreleased`: the rename, the config fallback and the package
   migration.
7. Repo rename after this lands (GitHub redirects the old URLs), then update
   the local remote.

## Verification

- `cargo fmt --check`, `cargo build --workspace`, `cargo test --workspace`,
  `cargo clippy --workspace --all-targets -- -D warnings`.
- `scripts/check-release-version.sh` against the renamed files.
- `nfpm` config renders (`nfpm package --packager deb --target /tmp`).
- A dry `make install DESTDIR` tree listing shows the new binary, desktop,
  metainfo, icon and udev paths.
- The renamed CLI still talks to the board (`lk67ctl light get`).
- Release 0.3.0 (breaking rename) after merge; assets follow the new name.
