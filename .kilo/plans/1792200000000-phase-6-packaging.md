# Phase 6: packaging and docs

Status: **done and released as 0.1.0**, verified on this machine and in CI.
Branch `feat/phase-6-packaging`.

The first release also carried a full code-quality and security audit of the
whole tree (four independent passes: FFI/ioctl, write-path safety, untrusted
input, and quality/supply chain) plus a README pass; what that changed and what
it deliberately deferred is in `CHANGELOG.md` and the PR for this branch.

All four formats were built and inspected: deb (control + file list via `ar`/`tar`),
rpm (`rpm -qpi/-qpl`), AppImage (its CLI read the board and its GUI connected),
and Arch (`makepkg` from a synthesised tarball; 25 icon files, `.PKGINFO` deps,
`.INSTALL` scriptlet, and the packaged binary ran).

## Goal

Ship installable packages for **Arch**, **Debian/Ubuntu**, **Fedora/RHEL** and a
portable **AppImage**, built reproducibly from a tag, with the udev rule and the
desktop entry in the right places for each format, and documented.

## Decisions

**One tool per package family, no hand-rolled scripts.**

| format | tool | why |
|---|---|---|
| deb + rpm | `nfpm` | one YAML for both, with per-format dependency blocks; no `control`/`.spec` pair to keep in sync. Present in neither repo nor base system, so CI downloads the released binary and the Makefile takes `NFPM` as a variable. |
| Arch | `makepkg` + `packaging/arch/PKGBUILD` | Arch convention; already in the repo. |
| AppImage | `appimagetool` | the standard; the AppDir is assembled by the Makefile, no `linuxdeploy` needed (see "What the AppImage bundles"). |

`rpmbuild` is installed as a fallback for inspecting a `.rpm`, and `dpkg-deb` is
not required — `ar t`/`ar x` reads a `.deb` without it.

**Versions come from one place.** The workspace `Cargo.toml` version is the
source; `scripts/check-release-version.sh` asserts the PKGBUILD's `pkgver` (which
Arch needs as a literal) and the tag agree with it. nfpm and the AppImage take
`VERSION` from the environment.

**Build against the oldest glibc we support.** CI builds on `ubuntu-22.04`
(glibc 2.35) so the deb/rpm/AppImage run on 22.04+, Fedora 36+ and Arch; a
release built on `ubuntu-latest` would silently require a newer glibc.

**What the AppImage bundles.** The binaries, the desktop entry and the icon. Not
the display/GPU stack: `gamakay-gui` loads `libxkbcommon`, Wayland/X11 and the
GL/Vulkan loader with `dlopen` at runtime, so they never appear in `ldd`, and
bundling them for older hosts is a recipe for a library clash on newer ones —
every desktop already has them. It also does not bundle a font: the UI's legends
use the system sans (the bundled Noto Emoji is compiled in). Both are stated in
`docs/packaging.md` so the omission is deliberate and visible.

**AppRun dispatches.** `AppRun` sends a CLI subcommand (`list`, `info`, `light`,
`keymap`, `macro`, `apply`) to `gamakay` and everything else to `gamakay-gui`,
so one AppImage is both the app and a usable CLI — and so the package can be
tested without a display.

**udev and root.** All four formats ship the rule but cannot install it: it goes
to `/etc/udev/rules.d` (deb/rpm postinstall does it, AppImage cannot). The
`gamakay-gui` and `gamakay` binaries work without it for read-only use on a
system where the user owns the node; without the rule the user sees the existing
"install the udev rule" hint. Documented per format.

## Deliverables

1. `packaging/icons/gamakay.svg` plus the hicolor PNGs, generated by
   `scripts/make-icons.sh` (`rsvg-convert` + ImageMagick) and committed so a
   package build needs no image tooling. The desktop entry already says
   `Icon=gamakay` and no icon existed; the AppImage cannot be built without one.
2. `packaging/nfpm.yaml` — binaries, udev rule, desktop entry, icons,
   license/credits, per-format depends, postinstall.
3. `packaging/appimage/` — `AppRun` and the AppDir layout notes.
4. `packaging/arch/PKGBUILD` fixes: install the icons, note the udev reload, and
   `pkgver` kept in step with the check script.
5. `Makefile`: `package-deb`, `package-rpm`, `package-arch`, `package-appimage`,
   `packages` (all four), and `package-verify` to inspect what was produced.
6. `scripts/check-release-version.sh` and `.github/workflows/release.yml`: on a
   `vX.Y.Z` tag, guard the versions, build on 22.04, produce the four artifacts
   and attach them to the release.
7. `docs/packaging.md` and a README "Install" section.

## Verification

Every format is built on this machine before the phase is called done, and
inspected: `makepkg` against a locally made tarball, `nfpm` for deb+rpm with
`ar t` and `rpm -qpl` to list contents, and `appimagetool` with `--appimage-extract-and-run`
followed by running the AppImage's CLI against the attached board — which is the
one end-to-end check that the packaged binary really talks to the keyboard.
